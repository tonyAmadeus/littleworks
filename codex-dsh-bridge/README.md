# Codex–DeepSeek Harness 双向聊天桥接

版本：0.1.0 · Windows 本机分发版

本组件连接同一台 Windows 电脑、同一操作系统账户中的 Codex Desktop 与 DeepSeek Harness Desktop（DSH），使两端 AI 在各自原生聊天框中发送、接收并回应对方发言。SKILL 用于指导 Codex，程序负责真实来源核验、窗口配对、后台消息关联和监听。

## 适用条件

| 项目 | 要求或边界 |
| --- | --- |
| 操作系统 | Windows；本版未提供 macOS / Linux 适配 |
| Codex | Desktop 已登录并能聊天；已安装 codex-app-tools 插件。源环境验证版本为 0.1.5 |
| DSH | Desktop 0.2.0-rc.2；程序对其他版本拒绝启用，须先验证接口兼容性 |
| 执行环境 | Node.js 22 以上；启动文件可复用 Codex 暴露的 Node 路径 |
| 运行条件 | 两款桌面应用均运行，使用者有权访问本机账户与所选工作区 |
| 通讯范围 | 本机已授权聊天。不是跨电脑、跨账户或 ChatGPT 网页通讯服务 |
| 模型费用 | 发言使用两端现有模型及账户，会消耗各自正常用量 |

只安装 SKILL 或只运行 DSH，不能独立完成桥接。分发包复用已安装应用的本机接口，包含的适配代码不代表应用厂商提供永久兼容承诺。

## 安装

1. 将整个目录解压到固定位置，例如 `D:\Tools\codex-dsh-bridge`。保留目录结构。
2. 打开两款桌面应用，在分发包目录执行 `setup.cmd doctor`，查看依赖检查结果。该步骤不启用对话、不发送模型消息。
3. 在真实 Codex 聊天中明确提出安装授权，例如：

   > 请安装并启用 D:\Tools\codex-dsh-bridge 中的双向聊天组件，允许现有和新开窗口在我明确联络时互聊，并允许未绑定时自动创建对方聊天窗口。请执行安装并核验。

   Codex 在其真实聊天环境运行：

   ```powershell
   & 'D:\Tools\codex-dsh-bridge\setup.cmd' install --authorize-dialogue --allow-create
   ```

   不授权自动创建时省略 `--allow-create`，后续使用明确目标绑定。
4. 重启 DSH，并新开 Codex 聊天，使适配器和技能加载。告诉 Codex“检查并启动 DSH 监听”，再测试两端通讯。

不能在普通终端中复制或手动设置 CODEX_THREAD_ID 来模拟安装来源。实际 Codex 聊天身份由本机应用接口核对。自定义目录、已有安装和移除方法见 [安装说明](docs/INSTALL.md)。

## 使用

在 Codex 说“告诉 DeepSeek：一起讨论这个设计”，或在 DSH 说“告诉 GPT：请评价这个方案”。两端均按需要检查并启动共享监听；后台负责保存关联，不要求使用者为每次发言编写 JSON。

回复某条消息时回到该消息的实际来源窗口。主动发起时优先使用指定目标，其次当前窗口的登记配对；没有配对且安装时已授权自动创建时，新建对方聊天并登记。多个配对各自运行，普通窗口在首次明确联络之前不全量同步。

“先停一停你们不要聊了”暂停当前窗口选中的配对，监听和绑定保留，其他配对继续。说“恢复互聊”或“接着聊”可以恢复，暂停期间旧消息不会重放。自然收尾检查问题、待办、交付及投递状态；双方末句确认实际接收后进入待命。自然待命可由人类新话题继续，人工暂停须明确恢复。

发言正文不显示协议前缀、编号、协作 JSON 或回执报告。后台状态 published、accepted、observed 分别表示本地发布、接口接受和接收端实际核对，不混同为已读。详见 [使用说明](docs/USAGE.md)。

## 文件与数据

程序、DSH 适配器、技能、安装工具和离线测试包含在分发目录内。`bridge.config.json` 在安装时生成；聊天登记、正文、回执和日志保存在使用者自己的状态目录，默认 `%LOCALAPPDATA%\CodexDshBridge\state`。

分发包不包含既有聊天记录、窗口绑定、凭据、会话 Cookie、私人工作区文件、桌宠资产或第三方应用程序。应用凭据仅在本机读取，用于该账户原有认证；临时连接凭据不写入分发包。

## 验证与兼容性

离线测试：在目录运行 `npm test`，无需 npm install；全部依赖由 Node 内置模块及已安装 DSH 提供。诊断入口为 `setup.cmd doctor`，实际监听验证由真实 Codex 聊天执行 `channel.cmd ensure`，DSH 使用 ensure_listener。

本版已在开发机的隔离目录验证可移植路径、安装文件生成和核心对话规则；完整两端原生互聊已在源安装中验证。尚未在另一台物理电脑完成安装验收。收件人应按 [验收步骤](docs/USAGE.md#安装验收) 验证，不将静态依赖检查视为实际投递成功。

本机接口变化、应用退出、权限提示和未知投递的处理见 [故障排查](docs/TROUBLESHOOTING.md)。分发与第三方组件说明见 [NOTICE.md](NOTICE.md)。
