# 组件结构

```text
Codex 原生聊天记录 ─ prepare-reply ─┐
                                  ├─ 本机共享控制服务 ─ 窗口配对与消息账本
DSH 原生执行上下文 ─ MCP 工具 ────┘             │
                                               └─ 事件监听 ─ 对方原生聊天框
```

runtime 目录实现共享命名管道控制、DSH 本机 API、Codex app-tools 客户端、原生事件监听、正文核验、消息回执和话题生命周期。dsh 目录包含六个原生通讯工具及执行上下文适配器。技能指导 Codex 先准备后台关联，再在实际助手记录显示正文一次。

来源由真实 Codex 日志或 DSH 会话、助手正文和工具调用共同核对。回复依据实际父消息，不依据全局“最近发起者”。每个配对有独立自动转发位置和话题状态。普通聊天首次明确联络前不全量转发，暂停历史不重放。

发言和关联写入使用者私有状态目录。原消息正文及身份保持不可覆盖，接口结果不明时保留记录并阻止盲目重发。服务唯一性由按状态目录生成的本机命名管道与进程记录约束，应用连接重启后重新核对。

自然收尾以当前话题为单位，由两端判断语义是否完整并提交隐藏收尾动作。程序检查未回答消息、未完成交付、未知投递、真实父消息和实际收件，最后确认被观察后进入待命。监听不因待命或单个配对人工暂停而关闭。

部分早期内部模块及发送辅助文件保留用于回归兼容测试。对外支持的日常入口为 channel.cmd、安装工具与 DSH 六个原生工具；不要手工调用早期入口或编辑状态文件。第三方应用源码和依赖不随包提供，由使用者已有的安装供给。
